Generic OTP
===========

``GenericOtp`` generates random decimal challenges for email, SMS, voice, or
application-specific confirmation flows. It requires a purpose-specific HMAC
key and one safe CacheLayer authentication-state cache. State is managed directly
through CacheLayer; no
OTP-specific store or adapter is required.

Construction
------------

.. code-block:: php

   use Infocyph\OTP\GenericOtp;

   $otp = new GenericOtp(
       cache: $stateCache,
       key: $genericOtpHmacKey,
       digits: 6,
       ttlSeconds: 300,
       maxAttempts: 3,
   );

Configuration bounds are:

.. list-table::
   :header-rows: 1

   * - Parameter
     - Allowed value
     - Default
   * - ``key``
     - 16–1024 raw bytes
     - Required
   * - ``digits``
     - 6–10
     - 6
   * - ``ttlSeconds``
     - 1–86400
     - 300
   * - ``maxAttempts``
     - 1–10
     - 3
   * - Binding
     - 1–4096 bytes
     - Required per operation

Use a key generated by a cryptographic key-management process. Do not use a
password, factor secret, application name, or the recovery-code HMAC key.
``$stateCache`` must use an isolated namespace, payload integrity,
``CacheOptions(failOpen: false)``, one authoritative backend, and CacheLayer's
configured state lock. Unsafe caches are rejected by the constructor. Complete
Redis, PDO, and local-development setup examples are in :doc:`storage`.

Issue and deliver
-----------------

.. code-block:: php

   $challengeId = bin2hex(random_bytes(16));
   $binding = 'email-login:user-42:' . $challengeId;

   $plainCode = $otp->generate($binding);

   try {
       $mailer->sendLoginCode($destination, $plainCode);
   } finally {
       unset($plainCode);
   }

``generate()`` creates unbiased random decimal digits and writes the complete
record under the binding-specific lock before returning. If lock acquisition or
the CacheLayer write fails, an exception propagates and no plaintext code is
returned. Issuing another code for the same binding atomically replaces the
prior record and invalidates the prior message.

Choose a binding that identifies the exact flow. This permits two legitimate
sessions for one account to have independent challenges and prevents a code
from one purpose being accepted for another.

Verify
------

.. code-block:: php

   $valid = $otp->verify($binding, $submittedCode);

A successful verification consumes the record, so every later attempt returns
``false``. A decimal code with the configured width that does not match decrements
the remaining-attempt counter. The record is deleted when attempts reach zero.

Malformed input—wrong width or non-decimal characters—returns ``false`` before
the cache or lock is touched. This avoids treating arbitrary oversized
input as a password attempt, but the application must still rate-limit every
request, including malformed ones.

Cancel
------

.. code-block:: php

   $removed = $otp->delete($binding);

``delete()`` cancels only the active challenge for that binding and returns true
when the CacheLayer deletion completes. Missing keys are successful no-ops under
PSR cache semantics. A lock or backend failure throws.

Expiration behavior
-------------------

The package captures an absolute ``expiresAt`` timestamp during issuance and
also supplies CacheLayer's relative TTL. Verification removes a record when
``expiresAt <= now``. A failed attempt writes the decremented record with only
the original remaining lifetime; it never converts expiration into a sliding
TTL.

Storage representation
----------------------

The public binding is transformed into separate fixed-size SHA-256 state and
lock keys. CacheLayer receives one native array:

.. code-block:: php

   [
       'v' => 1,
       'digest' => $hmacSha256Hex,
       'remainingAttempts' => 3,
       'expiresAt' => $absoluteUnixTimestamp,
   ]

Unknown versions, wrong types, or impossible values cause an exception rather
than an authentication miss. The candidate digest is:

.. code-block:: text

   HMAC-SHA-256(key, "generic-otp" || NUL || binding || NUL || otp)

This domain separation and binding prevent the same plaintext code from having
the same digest across purposes. Cache keys do not contain the original binding,
and CacheLayer never receives the plaintext code.

Concurrent requests
-------------------

The shared CacheLayer backend and lock provider guarantee these outcomes:

* two concurrent correct attempts produce exactly one success;
* each well-shaped wrong attempt decrements exactly one attempt;
* a wrong-attempt race cannot revive an expired or exhausted code;
* issue racing verification leaves either the new issued record or a consumed
  state consistent with serialization order; and
* deletion cannot partially update a record.

See :doc:`storage` for supported backend patterns.

Delivery and application policy
-------------------------------

The package does not provide:

* email, SMS, voice, or push delivery;
* destination verification;
* resend cooldowns;
* per-account, per-IP, or per-destination throttles;
* user/account enumeration defenses;
* session binding;
* login completion;
* audit retention; or
* provider webhook processing.

Apply these controls around every call. Avoid revealing whether a destination
exists. Do not log the plaintext code, HMAC key, submitted input, or provider
message body.

Production example outline
--------------------------

.. code-block:: php

   try {
       if (!$limiter->allow($accountId, $requestIp)) {
           return $genericFailure;
       }

       $valid = $otp->verify($bindingFromSession, $request->otp());

       if (!$valid) {
           return $genericFailure;
       }

       $session->rotate();
       $audit->record('generic_otp_authenticated', ['account' => $accountId]);

       return $success;
   } catch (Throwable $exception) {
       $logger->error('Generic OTP state unavailable', [
           'exception_class' => $exception::class,
       ]);

       return $temporaryFailure;
   }

The exception log intentionally excludes binding, code, destination, and keys.
